# `features/admin/` — administrator screens

Routes: `/admin/agenda`, `/admin/agenda-pendiente`, `/admin/especialistas`, `/admin/horarios`, `/admin/cursos`, `/admin/asesorias`. Every write goes through `AgendaApi` and is re-validated by Postgres; the screen only presents results.

- **Conflicts:** changing weekly hours, saving a block or deactivating a specialist can fail with `ErrorConflicto` (future confirmed appointments would be stranded). Catch it and call `mostrarConflictos()` (`conflictos.ts`), which lists the affected appointments. Never cancel appointments to make a change pass.
- **Weekly schedule:** the editor replaces the whole week with one `admin_set_weekly_schedule` call. Do not delete + insert from the client: the deferred conflict check would reject the intermediate state. Client-side validation (overlaps, end > start) is only a convenience.
- **Blocks:** `formulario-bloqueo.ts` converts "all day" ranges to `[00:00, next day 00:00)` in Bogotá time; notes must not contain health data.
- **Creating specialists** (`formulario-especialista.ts`) calls the `admin-users` Edge Function (invite by email → the person sets their own password at `/restablecer`). New specialists have no hours until configured in Horarios, so they offer no slots.
- **Known gaps:** the modal only creates *new* specialists; seeded specialists without a user cannot be granted access from the UI (the Edge Function's `change_email` returns 404 for them), they are linked by SQL. Removing a specialty from a specialist with future appointments of that specialty is not validated.
- **New appointment** (`nueva-cita.ts`): patients are identified by document type + number (phone is contact only and may repeat); an existing patient's names are shown and never overwritten; the "autorización de datos" checkbox is required. `selector-cupos.ts` shows the real free slots (via `admin_free_slots`) in 14-day windows and keeps the dialog's choice as an ISO instant.
- **Cursos** (`cursos.ts`, read-only, migration 20): there is no courses table. The catalog is the chatbot menu (`bot_nodos`: `info` nodes under a branch with `accion = 'inscripcion'`; the branch is the category, an intermediate submenu the "grupo") and the enrolments are `bot_inscripciones`; both belong to the chatbot engine and are read only through `AgendaApi.cursos()` / `inscripciones()` → `admin_cursos` / `admin_inscripciones`. Never query `bot_*` tables directly or add policies to them. The screen shows only the filters and the table (the catalog cards were removed at the user's request); the catalog just fills the «Categoría» and «Curso» filters. Enrolment status (pendiente/contactado/matriculado/cancelado) is shown but cannot be changed yet.
- **Asesorías** (`asesorias.ts`, read-only, migration 21): same pattern as Cursos. Catalog = `info` nodes under the menu branches with `accion = 'servicio'` (Asesoría jurídica, Asesorías generales; the «Simposios y bienestar empresarial» submenu is a group inside generales). Requests = `bot_solicitudes` with `tipo = 'servicio'` only (that table also stores appointment requests and emergencies, which must not appear here). A request linked to a branch instead of a specific type shows as «<rama>: sin tipo específico». `detalle-solicitud.ts` shows the case text (`detalle`), which may be sensitive (Ley 1581): admin only. Status (pendiente/contactado/agendada/atendida/cancelada) is shown but cannot be changed.
- **Agenda pendiente** (`agenda-pendiente.ts`, migrations 24–25): «open» appointment requests the bot saves when it cannot book online — the person types the day/time they prefer (`preferencia`). They are `bot_solicitudes` with `tipo = 'cita'` (motivo: «Sin agenda en línea» for services without specialists such as Fonoaudiología, Optometría and Fisioterapia; «Atención a domicilio»; «Error al agendar automáticamente»; or a reschedule with no free slots, which has no menu service and shows under «Otros»). The screen shows **only the filters and the table** (no catalog cards — the user asked to remove them). `serviciosCita()` just fills the «Servicio» filter (health services = `info` nodes under the menu's `accion = 'cita'` branch, `agenda.servicios_cita_nodos()`); its `agenda_en_linea` / `pendientes` columns are currently unused by the UI. Read through `AgendaApi.serviciosCita()` / `citasPendientes()` → `admin_servicios_cita` / `admin_citas_pendientes`. The admin changes each request's status (any of the five) from the detail dialog `detalle-cita-pendiente.ts` → `AgendaApi.cambiarEstadoCitaPendiente()` → `admin_cambiar_estado_cita_pendiente`; it sends the status being viewed, so a concurrent change returns `status_changed` and the list reloads. Changing status never books an appointment nor notifies the patient; these requests are not appointments until staff book them in Agenda.
- Cursos and Asesorías share `agrupar-catalogo.ts` (generic grouping by category, display only; used for the «Categoría» filter and the results title). No screen shows catalog cards anymore; the global classes `.contador` and `.titulo-resultados` remain in `styles.scss`.
- Dialogs are one component per file (`nueva-cita`, `reprogramar-cita`, `cancelar-cita`); reschedule is atomic server-side, so a failed new slot leaves the original appointment untouched.
